## Advertising

- **Shape.** `AdsController` (main) is the only thing shared code knows about ads: `canShowAds`, `privacyOptionsRequired`, `adsAreLive`, `start`, `showPrivacyOptions`. `foss` binds a no-op; `commercial` binds `AdMobAdsController` through a per-flavor Koin `adsModule`. The banner composable `AdBanner` has the same signature in both flavors (empty in foss), so screens contain no flavor checks.
- **Consent first.** Google's consent flow runs before anything is requested; the ads SDK starts (off the main thread) only once the service says ads may be requested. Where required, the Top Repos menu offers a way to reopen the privacy choices.
- **Safe by default.** Sample ids in every build unless `-PadmobProduction=true`, which fails at Gradle configuration if any of the three real ids (`admobAppId`, `admobBannerUnitId`, `admobRewardedUnitId`) is missing. The ids are read from a Gradle property or `local.properties`, never from the committed `gradle.properties`. So test ads cannot be shipped as live ones by accident, and a live build cannot be made without real ids. Debug always uses sample ids.
- **Test devices.** Every build that is not a production build registers the emulator and, if set, the developer's own device (`ADMOB_TEST_DEVICE_ID` in `local.properties`) as test devices, so even a live unit shows them test ads. Production builds register none; testers' phones are registered in the AdMob console.
- **Live marker.** `adsAreLive` puts `LIVE ADS` in the drawer's build label, so a live build is never mistaken for a test one. The foss build has no trace of it in BuildConfig.
- **Ads kit.** `scripts/export-ads-kit.sh` generates a kit (`build/ads-kit` and a zip) that another project can drop in or read as a reference: the ads source files with the package turned into a placeholder, the Gradle, dependency, string and backup-rule snippets cut from the real files between `ads-kit:` markers in `app/build.gradle.kts`, the foss-clean script, the ads docs, an integration guide, and an `install.sh` that swaps in the other project's package. It is generated from the current files, so it cannot drift; keep the markers when editing the Gradle file. The kit's ViewModel is written against a plain `ViewModel` plus `KoinComponent`, so it does not need this app's base ViewModel. The export fails if anything naming this app's package is left in the kit.
- **Why this much care.** Clicking your own live ads, or inviting others to, counts as invalid traffic and can end an AdMob account. See `docs/ads-testing-rules.md`.

## Ad-free offer

- **What it is.** The user can watch one rewarded video and get one hour without the banner. Opt-in only: the offer is a small line in the title bar (above the repo count on Top Repos, under the title on repo issues, plus a backup menu entry on Top Repos). While a period runs the line shows the minutes left.
- **Where the logic is.** `AdFreePeriod` and its saved end time live in `src/commercial`, so the open build holds none of it. The shared `AdsController` interface gains `adFreeUntilMs`, `canOfferAdFree` and `showAdFreeOffer(activity)`; the foss build returns "never". `canShowAds` is false while a period runs, so the banner (wrapped in `AdBannerSlot`, which slides it in and out) hides by itself and returns when the hour ends.
- **Rules.** The period starts only when the video is finished. It cannot be started again while running. It is saved on the device and excluded from backups. The end time comes from the device clock; a saved end more than one period ahead is cut back to one period, which caps clock tampering.
- **Video loading.** One rewarded video is preloaded once ads are allowed and no period is running. A failed load waits 60 seconds before the next try. The offer shows only while a video is ready, so it never offers something that fails.
- **Offline.** The banner reports a network failure by showing plain, muted text ("You're offline") in its reserved strip until an ad loads. The banner does not move, so the layout does not jump.
- **Ids.** Debug always uses Google's sample rewarded unit; a production build needs `admobRewardedUnitId` with the other two.
